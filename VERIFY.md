# Проверка сборки «Ткач Ярусов»

Документ фиксирует, что именно проверено и какими числами это подтверждено.
Все замеры сделаны инструментами из этого же репозитория, без ручной оценки.

## 2. Локальный статический сервер

Сервер раздаёт файлы без сжатия — именно так на них смотрит Unity WebGL.

| Адрес | Ответ | Размер | Content-Encoding |
|---|---|---|---|
| `/` | 200 | 6 600 | нет |
| `/Build/webgl.loader.js` | 200 | 48 779 | нет |
| `/Build/webgl.framework.js.unityweb` | 200 | 75 096 | нет |
| `/Build/webgl.data.unityweb` | 200 | 4 157 853 | нет |
| `/Build/webgl.wasm.unityweb` | 200 | 8 558 224 | нет |
| `/privacy.html` | 200 | 7 509 | нет |
| `/TemplateData/style.css` | 200 | 1 666 | нет |

Итого: **7 из 7 адресов по 200, ни одного со сжатием** — это главная причина белых экранов
при публикации WebGL на статическом хостинге, и здесь её нет.

Отдельно пройден **весь архив целиком**: 18 файлов из 18 отдаются по 200 и без сжатия
(включая картинки шаблона, иконку и политику). Проверка запускается так:

```
node C:\Unity\tools\serve.mjs C:\Unity\Loomfall\docs 8082
# затем перебором всех файлов каталога docs: Invoke-WebRequest по каждому
```

У сервера два аргумента именно в этом порядке — `папка`, потом `порт`; перепутанные
местами дают «невозможно соединиться» вместо ошибки.

| Импорты моста в wasm (сторона C#) | `LoomfallInit`, `LoomfallStorageGet`, `LoomfallStorageSet`, `LoomfallShowAd`, `LoomfallFree` — все по 1 |
| Проверка моста к площадкам | **15 из 15** на подставных SDK (`node Tools/bridge-test.mjs`) |
| Версия VK Bridge на странице | закреплена: `@vkontakte/vk-bridge@3.0.2` |
| Настоящих ошибок на странице | **0** (семь найденных «error» — это комментарии в шаблоне Unity) |

Интеграция площадок проверена в три слоя, потому что однажды она уже молча выпала
из сборки: **мост** (тест с подставными SDK), **собранный движок** (строки вызовов в
`Build/webgl.framework.js.unityweb`) и **сторона C#** (импорты `Loomfall*` в `Build/webgl.wasm.unityweb`).
Оба файла сжаты gzip, поэтому сначала распаковываются — иначе поиск по тексту ничего
не найдёт и покажется, что интеграции нет (на этом я один раз уже ошибся).

Хром для этой проверки запускается **только со своей папкой профиля**
(`--user-data-dir=<папка>`): без неё он молча не отдаёт ни страницу, ни снимок, и
проверка выглядит как «пустой результат». Ошибки хрома при этом тоже нужно смотреть,
а не гасить: «Missing value path for key …Extensions…» — обычный шум Windows, он не мешает.

## 7. Как повторить

Команды для PowerShell — одной строкой, он не понимает перенос через `\`:

```
# пересобрать сцену, игру и архив
Unity.exe -batchmode -nographics -quit -projectPath <проект> -executeMethod Loomfall.EditorTools.LoomfallCore.SetupAndBuild -logfile build.log

# поднять статический сервер на архиве (сначала папка, потом порт)
node tools/serve.mjs <проект>/docs 4185

# проверить в headless Chrome (обязательна своя папка профиля)
chrome --headless=new --disable-gpu --no-sandbox --user-data-dir=<папка профиля> --virtual-time-budget=30000 --window-size=1280,720 --screenshot=shot.png --dump-dom http://127.0.0.1:4185/

# прогнать игру живьём (вход в play-режим и 600 кадров)
Unity.exe -batchmode -projectPath <проект> -executeMethod Loomfall.EditorTools.LoomfallPlay.Run -logfile play.log

# проверить управление, заставку и профиль качества (20 проверок)
Unity.exe -batchmode -quit -projectPath <проект> -executeMethod Loomfall.EditorTools.LoomfallTouch.Run -logfile touch.log

# проверить мост к площадкам на подставных SDK (15 проверок)
node Tools/bridge-test.mjs

# убедиться, что вызовы площадок попали в собранный движок
# (файлы Build/*.unityweb сжаты gzip — сначала распаковать)
```

Две ловушки, на которых я уже спотыкался:

- **Добавили компонент в построитель — пересоберите сцену** (`LoomfallRuntime.Setup`).
  Иначе компонента в сцене нет, прогон покажет «заставки нет» и «ввод не блокируется»,
  и это будет ложный результат, а не ошибка игры.
- **Пакетный прогон идёт в тысячи кадров в секунду**: кадр длится доли миллисекунды,
  поэтому проверки «через полсекунды» внутри прогона не наступают никогда. Такие
  правила проверяются тестом (`IntroScreen.ShouldClose`), а сцена — вызовом `Dismiss()`.
